## Decisions that genuinely need the user

1. **Stage 1A verdict after evidence:** reject, revise, or advance the unmodified-arrow hypothesis once the blocking branded-Chrome and assistive-technology observations exist.
2. **Browser lane adoption:** separately approve a browser-automation dependency or custom controller if deterministic production-DOM execution is required before Stage 1B.
3. **Accessibility release bar:** later decide whether candid non-interference limitations are sufficient or first-class screen-reader arrow operation requires a different interaction model.
4. **Future telemetry architecture:** later approve or reject the complete privacy-minimized first-party implementation proposal; Stage 1A remains unchanged until then.
5. **Remaining compliance decisions:** identify private-test participants/data handling, select the later donation provider/payment jurisdiction, and decide how to resolve public-release legal questions when no outside counsel is planned.

Not required now: regional-domain support, browser-automation dependency choice, Store dashboard checkbox interpretation, privacy-policy hosting/support URL, and publisher ownership/2SV. Those become blocking only at their roadmap gate.
