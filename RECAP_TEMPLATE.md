# Operator progress-update template

Use this exact three-part structure only for unsolicited progress updates that the operator chat sends to the user. Keep them concise, high-level, understandable to a non-coder, and educational about the key idea. Direct answers to user questions remain natural. Project tasks and individual agents do not use this template for their own interfaces, internal reviews, briefs, or technical reports.

The operator chat is the sole normal human interface. Execution/review agents send findings and choices to the operator; the user is not asked to coordinate agents or read technical discussions. Surface through the operator only material product choices, safety/privacy/security concerns, new permissions or credentials, costs/dependencies, irreversible external actions, or human-only browser/accessibility validation.

## What we did

State the bounded work completed or checked.

## What it achieved

Explain the user, quality, safety, or decision value in plain language. Do not turn static evidence into a browser or real-user claim.

## Next step

State the next bounded action, unresolved gate, or decision. Do not imply authorization that has not been granted.
